# Glossary

One row per word the project uses in a specific sense. The **Meaning** column paraphrases
the document that owns the word; the **Defined in** column is that document, and it wins
whenever the two disagree. A row without a source does not belong here — this file points,
it does not define. Add a row when a word had to be explained twice; `tools/backlog/build.py
--check` reports a row whose link resolves to nothing, and an axis token that has no row.

The naming rule that this file serves is in [CLAUDE.md](../CLAUDE.md#vocabulary--read-the-projects-words-before-naming-anything):
read the vocabulary before naming anything new, build names from the words the model already
has, grep before you coin.

## Nodes, peers, and the wire

| Term | Meaning | Defined in |
|---|---|---|
| **node** | One running D-PC client with its own cryptographic identity: a human and their agents on one machine. Not the XML or DOM sense of the word used in other codebases. | [specs/dptp_v1.md §4](../specs/dptp_v1.md#4-node-identity-system) |
| **node_id** | `dpc-node-` plus the first 32 hex characters of the SHA-256 of the node's RSA public key; the certificate's Common Name and the key to everything that names a node. | [specs/dptp_v1.md §4](../specs/dptp_v1.md#node-id-format) |
| **peer** | Another node this node talks to over DPTP; its certificate is stored only after its key re-hashes to its claimed `node_id`. | [specs/dptp_v1.md §4](../specs/dptp_v1.md#identity-storage) |
| **DPTP** | D-PC Transfer Protocol: a 10-byte ASCII length header plus a JSON payload, carried over TLS, WebRTC data channels or DTLS. | [specs/dptp_v1.md §1–2](../specs/dptp_v1.md#1-overview) |
| **HELLO** | The first DPTP message on a connection, carrying the peer's `node_id` and display name; both sides send one. | [specs/dptp_v1.md §3.1](../specs/dptp_v1.md#31-connection-establishment) |
| **connection tier (1–6)** | One of six strategies the orchestrator tries in order — IPv6 direct, IPv4 direct, Hub WebRTC, UDP hole punching, volunteer relay, gossip store-and-forward. "Complete" in the roadmap means the code shipped, not that the tier carries traffic. | [CLAUDE.md — Connection Types](../CLAUDE.md#connection-types-6-tier-fallback-hierarchy---v0101), [ROADMAP.md — Decentralized Infrastructure](../ROADMAP.md#decentralized-infrastructure-v095---v0102) |
| **star topology** | The live shape of the three-node stand: every link goes through one node because host firewalls block inbound elsewhere; a configuration of a real user, not a defect to fix by opening ports. | [ROADMAP.md — Decentralized Infrastructure](../ROADMAP.md#decentralized-infrastructure-v095---v0102) |
| **peer cache** | `~/.dpc/peer_cache.json`, the last known address of each peer; what actually carries traffic when the DHT is empty. | [ROADMAP.md — Decentralized Infrastructure](../ROADMAP.md#decentralized-infrastructure-v095---v0102) |
| **DHT / seed nodes** | The Kademlia table a node uses to find peers, entered only through the `[dht] seed_nodes` config line; empty by default. | [CONFIGURATION.md `[dht]`](CONFIGURATION.md#dht) |
| **Hub** | The optional federation server: OAuth login and WebRTC signalling only, never message routing or storage; every direct path works without it. | [CLAUDE.md — Key Components](../CLAUDE.md#key-components), [specs/hub_api_v1.md](../specs/hub_api_v1.md) |
| **firewall / privacy rules** | `~/.dpc/privacy_rules.json`: what each peer or group may read of this node's context, whether compute and transcription are shared, what agents may use; hot-reloaded on save. | [CLAUDE.md — Context Firewall Rules](../CLAUDE.md#context-firewall-rules) |
| **transcription send-to** | The outgoing half of transcription sharing: `transcription.send_to_nodes` / `send_to_groups` in `privacy_rules.json` name the peers this node may hand its **own** audio to when local transcription fails. The opposite of `allow_nodes`, which lets peers use our Whisper; empty means never. Proposed 2026-09-07 with the fallback step — the vocabulary had a word for serving and none for sending. | [CLAUDE.md — Context Firewall Rules](../CLAUDE.md#context-firewall-rules) |
| **remote inference** | Running a model on a trusted peer's hardware over the encrypted P2P channel, seen from the side that asks: the requester picks the peer as compute host, and the host's firewall decides whether to serve. The host's side of the same exchange is **Inference Sharing**; "compute sharing" was that tab's name until 2026-09-14 and is kept only by the `compute.*` config keys. | [REMOTE_INFERENCE.md — Overview](REMOTE_INFERENCE.md#overview) |
| **Inference Sharing** | The firewall tab and the door that share this node's models with peers (ADR-041): which aliases are served, who may call them, who calls for free, at what tariff, and which models the door accepts. Named "Compute Sharing" until 2026-09-14 (Mike's call: the old name suggested lending a GPU, while what crosses is inference on the host's own model); the config section keeps the name `compute` until the key rename is decided. | [REMOTE_INFERENCE.md — Enabling Inference Sharing](REMOTE_INFERENCE.md#enabling-inference-sharing) |
| **node ledger** | `~/.dpc/ledger/usage-YYYY-MM.jsonl`: the node's own record of every model call it made or served — an agent's, a peer's or a gateway client's — kept by the node because the card and the vendor key are the node's. Monthly files, append-only, never rotated: a financial record does not lose rows on a schedule. | [decisions/041 D3](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called) |
| **usage row** | One line of the node ledger: who called (`caller`, **caller_kind**), what ran (`alias`, `model`, **route**), what it took, whose counts those are (**counts_source**), and what it cost — priced once, at the moment of the call, by the node that made it, and never re-derived. The columns added through 2026-09-14/15 carry the rest: **served_by**, the host of a call this node only consumed; **peer_proved** with `peer_connection_type`, whether the far end's key was proved and over which tier; **output_includes_thinking** and **thinking_source**, what is inside the counts and where the split came from; **served_effort**, the rung the call actually ran at; and the **tariff** group (`tariff_in`, `tariff_out`, `tariff_currency`, `tariff_at`, `tariff_amount`), what the owner charged for it. | [decisions/041 D3](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called) |
| **caller_kind / route** | The two columns of a **usage row** that together say whose call it was and where it ran: `caller_kind` is `agent`, `peer` or `gateway` — who asked — and `route` is `local` or `peer` — whose engine answered. There is no `gateway` route: the gateway is a caller, never a destination. The pair is what the ledger reads itself by (`node_ledger.usage_by_role`): `route=local` with `caller_kind=peer` is what this node *served*, `route=peer` is what it *consumed*, and the rest is its *own*. A value outside either vocabulary is refused at write time rather than written, because a row nothing can read is not a record. | [decisions/041 D3](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called) |
| **counts_source** | Where a **usage row**'s token counts came from, as the writer of that row knows it: `engine` — the numbers were received, from the engine this node called or from a host's answer on the wire, and this node counted nothing; `ours` — this node counted the text itself. A guest's `engine` is therefore not an assertion that an engine counted: a host that counted the text itself writes `ours` on its own row and sends the same numbers, which the guest records as `engine` (open card `TWO-NODES-WRITE-THE-SAME-TOKEN-COUNT-UNDER-TWO-DIFFERENT-WORDS`). It says where the numbers came from and never what is inside them — that is **output_includes_thinking** — and an exact total can hold an estimated split, which is what **thinking_source** is for. | [decisions/041 D3](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called) |
| **output_includes_thinking** | `includes` / `excludes` / `unknown`: whether a row's output count already holds the reasoning count, as declared by the node that produced the count rather than assumed from a convention. The word is what sets the billable output, and ADR-041 states the formula: `includes` → `tariff_out × completion_tokens`; `excludes` → `tariff_out × (completion_tokens + thinking_tokens)`, reasoning being billable output at `tariff_out` with no rate of its own; `unknown` → not billed, analytics only — the state of every row written up to that decision. A row written before the column reads as `unknown`. Under `includes` the reasoning is inside the output and never larger than it; a count that overflowed is clamped to the completion and marked `estimated`, so the record of a call that was made is kept rather than refused. | [decisions/041 D3, amendment 2026-09-13](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called), [specs/dptp_v1.md §3.4](../specs/dptp_v1.md#34-remote-ai-inference) |
| **thinking_source** | Where a row's `thinking_tokens` came from: `engine`, the host's vendor reported the reasoning split, or `estimated`, the host derived it from the reasoning text, which is what a build that reports no split sends. Null is silence — a node that said nothing, an older row, or a call with no reasoning — and is never a claim that an engine counted. Provenance, not arithmetic: the counts beside it can be exact while the split inside them is a guess, and a **tariff** is charged on the prompt and output counts either way. | [specs/dptp_v1.md §3.4](../specs/dptp_v1.md#34-remote-ai-inference) |
| **peer_proved** | On a **usage row**, whether the node at the other end of the call had its key proved on the connection the call travelled over — the line ADR-041 D2 draws for serving peer inference at all. `True` means one of two checks ran: inbound, the certificate's CN is the claimed `node_id`, its public key hashes to that `node_id`, and an RSA-PSS signature over a nonce this node chose verifies under it; outbound, the same CN and key hash over a TLS session that has already made the far end prove it holds the private half. `False` is a tier that runs neither, where the name is the Hub's assertion, this node's own intention or an envelope field. Null means there is no far end to prove — an agent or a gateway client on this machine is not reached over a tier — and is what a row written before the column reads as. `peer_connection_type` beside it names the tier the answer came from. | [decisions/041 D2](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d2--authorised-on-a-connection-whose-peer-key-has-been-proved) |
| **cost_usd** | What a call cost the node that ran it, in USD: a vendor's price computed once at the moment of the call, or 0 by construction for a local model; `null` on a guest's row, because the guest ran nothing and prices nothing. | [decisions/041 D3](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called) |
| **billing** | Which pool a call's cost belongs to — `subscription` or `pay_per_use` — as `dpc_agent/pricing.py` classifies the alias and model; a label on the usage row, not an amount. | [decisions/041 D3](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called) |
| **served_effort** | The usage-row column and `REMOTE_INFERENCE_RESPONSE` field naming the **reasoning effort** the host actually ran a call at — the rung its provider reports having sent, where the provider reports one, and otherwise the guest's word clamped to the host's cap or the alias's configured word. Null means no word describes the call — the alias has no **effort channel**, or its host could not read its own configured word — and is never the same as `off`. | **tariff** | The rate an owner declares for a shared alias — per 1M input and per 1M output tokens, in the node's currency, dated — applied once at the moment of a call and written into both nodes' usage rows as the applied values. `null` means no tariff was declared (a gift), `0` means declared free, `>0` means paid. Distinct from `cost_usd` (what the call cost the host) and from `charge`, which is reserved for the act of settlement. | [decisions/041 D3, amendment 2026-09-10](decisions/041-openai-compatible-gateway-as-a-dpc-surface.md#d3--one-usage-row-per-model-call-on-the-node-that-ran-it-carrying-who-called) |
| **served_by** | The node that ran a call this node only consumed: the host's `node_id` on a `route=peer` usage row, written beside the tariff group because the two answer one question together — what the call was charged and by whom. A `route=peer` row written before the column names no host and keys `remote:?:<alias>` (`node_ledger.UNKNOWN_HOST`), shown as "host not recorded": a node id is `dpc-node-<32 hex>`, so `?` is a name no host can have and the bucket collides with none. Fail-closed: absent means "not stated", never "no ceiling applies". | [specs/dptp_v1.md §3.5](../specs/dptp_v1.md#35-provider-discovery) |
| **refusal code** | The machine-readable word beside the prose `error` on an error `REMOTE_INFERENCE_RESPONSE`, naming at which of the host's gates the call was refused so that a refusal keeps its reason across the hop. The seven: `identity_unproved` (the connection's key was not proved — see **peer_proved**), `not_allowed` (the host's firewall does not let this peer ask for inference, or not for what it asked), `model_not_found` (the host serves no alias to this peer, or not the one named), `onward_sharing_refused` (the alias is itself somebody else's model, and what is shared is not shared onward), `invalid_value` (a gate that names the guest's own request — an effort word the alias has no **rung** for, or a `request_id` already in flight from this peer), `tools_unsupported` (tools sent to an alias with no native tool-calling path), `insufficient_quota` (the ceiling word). Distinct from known — the caller picker offers every node the application holds a name for, connected first — and from allowed, which is the **firewall / privacy rules** answer and no part of this field. | [`service.py` `get_status`](../dpc-client/core/dpc_client_core/service.py) |
